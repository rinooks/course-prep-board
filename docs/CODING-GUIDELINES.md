# 코딩 지침 — 도담섬에서 배운 것

도담섬 소스코드에서 잘한 부분만 추려 정리한 지침이다. 다른 프로젝트에도 그대로 적용할 수 있다.
(참고: 도담섬의 극단적으로 압축된 코드 스타일은 배울 점이 아니므로 여기에 포함하지 않았다.
코드는 압축하지 말고 읽기 좋게 쓴다.)

---

## 1. 실패하는 경우를 먼저 설계한다

좋은 코드와 그럴듯한 코드의 차이는 "잘 될 때"가 아니라 "안 될 때" 드러난다.
기능 하나를 만들 때마다 아래 질문을 던지고, 각각에 대한 대비책을 코드에 넣는다.

- **네트워크가 끊기면?** → 재시도하되, 간격을 점점 늘린다(지수 백오프: 1초 → 2초 → 4초 → 8초).
  실패할 때마다 즉시 재시도하면 서버가 살아나는 순간 요청이 몰려 다시 죽는다.
  - 도담섬: `multiplayer.js`의 sync 실패 처리. 3회 연속 실패하면 다른 접속자 표시도 지워서
    "끊겼는데 멀쩡해 보이는" 상태를 만들지 않는다.
- **같은 요청이 두 번 도착하면?** → 요청에 1회용 난수(nonce)를 붙여 서버가 중복을 걸러낸다.
  전송 버튼을 두 번 누르거나, 응답을 못 받아 재전송한 경우 데이터가 두 번 생기면 안 된다.
  - 도담섬: 채팅 전송 시 `crypto.randomUUID()`로 nonce를 만들고, 서버는
    `(sender_id, nonce)` 유니크 인덱스로 같은 메시지의 재전송을 기존 메시지 반환으로 처리한다.
- **저장소를 못 쓰는 환경이면?** → 기능을 끄되, 사용자에게 현재 상태를 알려준다.
  - 도담섬: localStorage 저장이 실패하면 조용히 무시하지 않고
    화면 문구를 "이 기기에 자동 저장" → "현재 플레이 중에만 기록"으로 바꾼다.
- **핵심 기능 초기화가 실패하면?** → 빈 화면 대신 원인 설명과 재시도 버튼을 보여준다.
  - 도담섬: 3D(WebGL) 초기화 실패 시 "최신 브라우저에서 하드웨어 가속을 켠 뒤
    다시 시도해주세요" 안내와 [다시 열기] 버튼을 띄운다.
- **응답이 안 오면?** → 모든 요청에 타임아웃을 건다. 무한 대기는 사용자를 가둔다.
  - 도담섬: 모든 fetch에 8초 타임아웃(`AbortController`).

## 2. 서버는 클라이언트를 절대 신뢰하지 않는다

클라이언트 검증은 사용자 편의일 뿐이다. 브라우저에서 오는 모든 값은 조작 가능하므로,
**서버에서 전부 다시 검증한다.** 클라이언트에서 이미 검사했더라도 예외 없다.

- **모든 입력값을 검증한다**: 길이, 형식, 허용 목록(enum), 좌표 범위까지.
  - 도담섬: 이름 1~16자, 채팅 1~300자, 캐릭터 조합은 허용된 조합인지,
    좌표는 섬 범위 안인지 서버가 검사한다. 섬 밖 좌표를 보내면 스폰 지점으로 되돌린다.
- **신원 정보는 요청 본문이 아니라 세션에서 가져온다.**
  클라이언트가 보낸 "내 이름", "내 ID"를 믿으면 사칭이 가능해진다.
  - 도담섬: 채팅 요청에 `senderId`, `name`을 담아 보내도 서버는 무시하고
    쿠키 세션으로 확인한 실제 사용자의 정보를 쓴다. 이걸 검증하는 테스트도 있다.
- **눈에 보이지 않는 입력도 방어한다**: 제어 문자, 폭 없는 문자(zero-width) 제거,
  유니코드 정규화(NFC) 후 검증.
- **요청 크기를 제한한다**: Content-Length 헤더만 믿지 말고 실제 읽은 바이트 수로도 검사한다.
  - 도담섬: 본문 4KB 제한을 헤더와 스트림 양쪽에서 건다.

## 3. 보안 기본값을 처음부터 깐다

나중에 붙이려면 어려운 것들이므로 첫 코드부터 넣는다.

- **비밀값은 해시로 저장한다.** 세션 토큰·비밀번호를 DB에 원문으로 두면
  DB가 유출되는 순간 전 사용자의 세션이 탈취된다.
  - 도담섬: 쿠키에는 토큰 원문, DB에는 SHA-256 해시만 저장. 조회 시 해시해서 비교한다.
- **쿠키는 가장 엄격한 옵션으로**: `__Host-` 접두사 + `Secure; HttpOnly; SameSite=Lax; Path=/`.
  HttpOnly는 자바스크립트의 쿠키 접근을 막고(XSS 방어), SameSite는 다른 사이트발 요청에
  쿠키가 실려가는 것을 막는다(CSRF 방어).
- **상태를 바꾸는 요청(POST)은 Origin 헤더를 검증한다.** 우리 사이트 화면에서 온 요청만 받는다.
- **속도 제한(rate limit)을 건다.** 없으면 봇 하나가 서비스를 마비시킬 수 있다.
  - 도담섬: IP당 10분에 입장 100회, 채팅은 1인당 1초 1회, 동시 접속 80명 상한.
  - 채팅 속도 제한은 "조회 후 판단"이 아니라 조건부 UPDATE 한 번으로 처리해서
    동시 요청이 겹쳐도 뚫리지 않는다(`UPDATE ... WHERE last_chat <= ? RETURNING ...`).
- **응답 헤더 기본 세트**: API 응답에 `Cache-Control: no-store`,
  `X-Content-Type-Options: nosniff`. 정적 자산에는 적절한 `Cache-Control`.
- **에러 메시지에 내부 정보를 담지 않는다.** 사용자에게는 다음 행동을 알려주는 문구만,
  상세 원인은 서버 로그에만 남긴다.
  - 도담섬: 사용자에겐 "섬 연결이 잠시 원활하지 않습니다", 로그에는 실제 에러 메시지.

## 4. 테스트는 실제 환경의 모양대로 쓴다

가짜(mock)를 겹겹이 쌓은 테스트는 가짜만 검증한다. 실물에 최대한 가깝게 만든다.

- **배포에 쓰는 진짜 마이그레이션 SQL을 테스트에서도 실행한다.**
  테스트용 스키마를 따로 만들면 두 스키마가 어긋나도 아무도 모른다.
  - 도담섬: 테스트가 `drizzle/0000_*.sql`을 그대로 읽어 인메모리 SQLite에 적용한다.
- **API는 함수 단위가 아니라 요청/응답 단위로 검사한다.**
  실제 `Request` 객체를 만들어 핸들러에 넣고, 상태 코드·헤더·본문을 확인한다.
- **보안 시나리오를 테스트에 포함한다**: 사칭 시도, 잘못된 Origin, 만료된 세션,
  속도 제한 초과가 실제로 거부되는지.
  - 도담섬: 응답 JSON에 `session_hash` 같은 내부 필드가 새어나가지 않는지도 확인한다.
- **시간에 의존하는 로직은 가짜 시계로 고정한다.** `Date.now()`를 그대로 쓰면
  테스트가 실행 시점에 따라 통과했다 실패했다 한다.
  - 도담섬: `t.mock.timers`로 시각을 고정하고 `tick()`으로 시간을 진행시킨다.
- **로직은 테스트하기 좋게 분리해둔다.** 계산·규칙(순수 함수)을 화면 코드와 섞지 않는다.
  - 도담섬: `state.js`의 `sellItems`, `awardQuest`처럼 상태 변경 규칙을 분리했다.
    (도담섬은 정작 이쪽 테스트를 안 썼다 — 분리했으면 테스트까지 쓰는 게 맞다.)

## 5. 리소스는 만들었으면 치운다

- **생성한 객체의 해제 함수를 짝으로 만든다.** 특히 반복 생성되는 것
  (3D 오브젝트, 이벤트 리스너, 타이머)은 해제 누락이 곧 메모리 누수다.
  - 도담섬: 캐릭터를 만드는 `character()`와 짝으로 `releaseCharacter()`가 있어
    지오메트리·텍스처를 dispose하고 씬에서 제거한다. 접속자가 나가면 즉시 호출된다.
- **공유 자원과 개별 자원을 구분한다.** 공유 캐시에서 온 것은 해제하면 안 된다.
  - 도담섬: 공유 지오메트리를 `Set`에 등록해두고, 해제 시 그 목록에 없는 것만 dispose한다.
- **서버 데이터에도 수명을 정한다.** 무한히 쌓이는 테이블은 언젠가 반드시 문제가 된다.
  - 도담섬: 채팅은 최근 하루·최대 500개, 만료된 rate limit 키는 주기적으로 삭제.
    청소 작업은 응답을 막지 않도록 백그라운드(`ctx.waitUntil`)로 돌린다.

## 6. 성능은 습관으로 챙긴다

거창한 최적화보다, 만들 때부터 넣는 작은 습관이 효과가 크다.

- **같은 것을 두 번 만들지 않는다.** 색·옵션이 같은 재질(material)은 캐시에서 재사용,
  기본 도형(geometry)은 하나 만들어 모든 곳에서 공유한다.
- **기기 상한을 정한다.** 고해상도 화면에서 픽셀 비율을 무제한으로 따라가면
  렌더링 부하가 기기에 따라 4배 이상 벌어진다.
  - 도담섬: `devicePixelRatio`를 1.6으로 제한. 미리보기 화면은 1.3 + 저전력 모드.
- **갱신 주기를 용도별로 나눈다.** 모든 것을 매 프레임 갱신할 필요 없다.
  - 도담섬: 렌더링은 매 프레임, 미니맵은 0.15초, 시계·리스폰 체크는 1초,
    저장은 6초 간격.
- **숨은 탭에서는 멈춘다.** `visibilitychange`에서 루프·오디오·폴링을 중단하고
  복귀할 때 재개한다. 배터리와 서버 자원을 아낀다.

## 7. 사용자 경험의 마지막 1%를 챙긴다

- **한국어 입력(IME) 조합 중 Enter를 구분한다.** 조합 중 Enter로 전송하면
  마지막 글자가 잘리거나 두 번 전송된다. `compositionstart/end`로 조합 상태를 추적한다.
- **모바일 키보드가 화면을 가리는 것에 대응한다.** `visualViewport`로 실제 보이는
  높이를 계산해 입력창을 키보드 위로 올린다.
- **접근성 라벨을 처음부터 단다.** 캔버스, 아이콘 버튼, 색상 선택지처럼
  글자가 없는 요소에 `aria-label`을 붙인다.
- **떠나는 순간에도 저장한다.** `pagehide`에서 저장하고, 서버 통지는
  응답을 기다리지 않는 `navigator.sendBeacon`으로 보낸다.
- **에러 문구는 다음 행동을 알려준다.** "오류가 발생했습니다"가 아니라
  "입력 내용은 그대로 두고 다시 시도해주세요"처럼 사용자가 할 일을 적는다.

## 8. 구조는 규모에 맞게, 역할은 파일 단위로

- **규모에 맞는 가장 단순한 구조를 선택한다.** 도담섬은 프레임워크 없이
  ES 모듈 분리만으로 충분한 규모였고, 실제로 그렇게 했다.
  작은 프로젝트에 큰 구조를 얹으면 구조 관리가 일이 된다.
- **파일 하나에 역할 하나.** 도담섬의 분리가 좋은 예다:
  월드 생성(world.js) / 게임 진행(game.js) / 상태·규칙(state.js) /
  통신(multiplayer.js) / 화면 조작(view-controls.js) / 서버 API(api.js).
  "이 버그는 어느 파일인가"에 바로 답할 수 있으면 잘 나눈 것이다.
- **빌드가 결과물을 검증하게 한다.** 빌드 스크립트 마지막에 결과물을 실제로
  실행해보고, 기대한 응답이 나오는지 확인 후 성공을 선언한다.
  - 도담섬: 빌드 후 번들된 Worker를 import해 `/`를 요청하고
    응답에 "도담섬"이 포함되는지 확인한다. 깨진 빌드가 배포되는 것을 막는다.
- **허용 목록으로 처리한다.** 정적 자산의 확장자처럼 종류가 정해진 것은
  "모르는 것은 통과"가 아니라 "목록에 없으면 실패"로 처리한다.
